# E1-3 Mini NPU Simulator

## 1. 프로젝트 소개

Python으로 AI의 MAC(Multiply-Accumulate) 연산 원리를 구현하는 Mini NPU 시뮬레이터를 개발한다.

- **MAC(Multiply-Accumulate)**: 같은 위치에 있는 숫자들을 곱하고 그 결과를 누적하여 더하는 연산
- **NPU(Neural Processing Unit)**: 신경망 연산에 특화된 처리장치. 본 프로젝트는 실제 NPU 하드웨어가 아니라 MAC 원리를 모의 구현한 프로그램이다.

## 2. 개발 환경

- 언어: Python (미션 요구 환경: Python 3.8 이상)
- 개발 도구: Visual Studio Code
- 운영 환경: Windows
- 외부 라이브러리 사용 없음
- Python 표준 라이브러리 `json`, `math`, `re`, `time`, `pathlib` 사용

## 3. 구현 기능

### 3.1 실행 메뉴

- 사용자 입력 모드 (3×3)
- JSON 데이터 분석 모드

```text
=== Mini NPU Simulator ===
1. 사용자 입력 (3×3)
2. data.json 분석
선택:
```

사용자가 `1`을 입력하면 `mode_input()`을, `2`를 입력하면 `mode_json()`을 실행한다. 그 외의 값은 `잘못된 선택입니다.`라고 안내한다.

### 3.2 3×3 필터 및 패턴 입력

- 2차원 리스트를 이용하여 필터와 패턴 저장
- `input_matrix()` 함수로 행 단위 입력 처리
- 행과 열 개수 검증
- 숫자 변환 오류 발생 시 재입력 처리
- 무한대나 NaN처럼 유한하지 않은 값은 `math.isfinite()`로 검사

사용자는 필터 A, 필터 B, 입력 패턴을 각각 3줄씩 입력한다. 각 줄은 `0 1 0`처럼 공백으로 구분된 숫자 3개로 구성한다.

### 3.3 MAC 연산 구현

MAC(Multiply-Accumulate)은 입력 패턴과 필터에서 같은 위치의 숫자를 곱하고 그 결과를 누적하여 더하는 연산이다.

외부 라이브러리 없이 중첩 `for` 반복문을 사용하여 구현하였다.

주요 코드:

```python
for i in range(len(pattern)):
    for j in range(len(pattern[i])):
        score += pattern[i][j] * filter_matrix[i][j]
```

- `len(pattern)`: 전체 행의 개수를 구한다.
- `len(pattern[i])`: i번째 행에 들어 있는 숫자의 개수를 구한다.
- `i`: 행의 인덱스(0부터 시작)
- `j`: 열의 인덱스(0부터 시작)
- `pattern[i][j]`: 패턴의 i행 j열에 저장된 숫자
- `filter_matrix[i][j]`: 필터의 같은 위치에 저장된 숫자
- `score +=`: 곱셈 결과를 기존 점수에 누적하여 더한다.

예를 들어 `i=1, j=0`이면 두 번째 행의 첫 번째 숫자를 선택한다.

### 3.4 MAC 연산 테스트

3×3 십자가 패턴을 필터 A(십자가), 필터 B(X)와 비교하였다.

**테스트 결과**

- 필터 A 점수: **5.0**
- 필터 B 점수: **1.0**
- 예상 결과와 실제 계산 결과 일치
- 테스트 결과: **PASS**

입력값의 개수가 잘못된 경우 오류 안내 후 재입력하도록 구현하였으며, 이를 실제로 확인하였다.

### 3.5 동점 처리 테스트

#### 테스트 목적

두 필터의 MAC 점수가 동일할 때 프로그램이 정상적으로 '판정 불가'를 출력하는지 확인한다.

#### 테스트 데이터

- 필터 A: X 패턴
- 필터 B: X 패턴에서 2행 3열의 값을 0에서 1로 변경
- 입력 패턴: X 패턴

#### 실제 실행 결과

- 필터 A 점수: **5.0**
- 필터 B 점수: **5.0**
- 최종 판정: **판정 불가**
- 테스트 결과: **PASS**

#### 원인 분석

필터 B의 2행 3열은 1이지만 입력 패턴의 같은 위치는 0이므로 MAC 연산 결과는 `0 × 1 = 0`이다.

따라서 두 필터의 MAC 점수가 모두 5.0으로 계산되었으며, 동점 처리 조건에 따라 '판정 불가'가 출력되었다.

이 테스트를 통해 **정확한 동점 처리 기능**이 정상 작동함을 확인하였다.

### 3.6 epsilon 허용오차 테스트

#### 테스트 목적

두 MAC 점수가 정확히 같지는 않지만 차이가 매우 작을 때, 허용오차(epsilon) 기준에 따라 판정 불가로 처리되는지 검증한다.

#### 테스트 데이터

- 필터 A: 첫 번째 값 1, 나머지 0
- 필터 B: 첫 번째 값 0.9999999999, 나머지 0
- 입력 패턴: 첫 번째 값 1, 나머지 0
- epsilon: `1e-9`

#### 예상 결과

- A 점수: 1.0
- B 점수: 0.9999999999
- 판정: 판정 불가

#### 판정 기준

두 점수 차이의 절댓값이 epsilon보다 작으면 두 점수를 사실상 동점으로 간주한다.

조건식:

```python
abs(score_a - score_b) < EPSILON
```

`EPSILON`은 `1e-9`(0.000000001)로 설정되어 있다.

#### 실제 테스트 결과

- 필터 A 점수: **1.0**
- 필터 B 점수: **0.9999999999**
- 판정: **판정 불가**
- 테스트 결과: **PASS**

#### 결과 분석

두 점수의 차이가 허용오차(epsilon = 1e-9)보다 작으므로 프로그램이 두 점수를 사실상 동점으로 처리하였다.

이를 통해 **epsilon 기반 점수 비교 기능**이 정상적으로 작동함을 확인하였다.

### 3.7 MAC 연산 시간 측정

#### 구현 목적

MAC 연산의 실행 시간을 측정하고 반복 측정을 통해 평균 연산 시간을 계산한다.

#### 구현 방법

- Python 표준 라이브러리 `time` 사용
- `time.perf_counter()`로 MAC 연산 시작 및 종료 시간 측정
- MAC 연산을 10회 반복 측정
- 측정한 시간의 평균을 ms 단위로 출력
- 사용자 입력 및 화면 출력 시간은 측정에서 제외

#### 실제 테스트 결과

| 패턴 크기 | 반복 횟수 | 평균 시간(ms) | 연산 횟수(N²) |
|---|---:|---:|---:|
| 3×3 | 10 | 0.002080 | 9 |

테스트 결과: **PASS**

#### 결과 분석

3×3 패턴은 총 9개의 위치에서 곱셈과 누적 덧셈을 수행한다.

10회 반복 측정 결과 MAC 연산 **1회당 평균 실행 시간**은 0.002080ms였다.

이 시간은 10회 실행의 총시간이 아니라 한 번 실행할 때 걸린 평균 시간이다. 실행 시간은 컴퓨터의 상태에 따라 달라질 수 있다.

### 3.8 JSON 자동 분석 테스트

#### 구현 내용

- Python 표준 라이브러리 `json`을 사용하여 `data.json` 파일 로드
- `json.load()`로 JSON 데이터를 Python 자료형으로 변환
- 5×5, 13×13, 25×25 크기의 Cross/X 필터 검증

`normalize_label()` 함수를 별도로 분리한 이유는 JSON 파일에서 같은 의미의 라벨이 다르게 입력되더라도 표준 이름으로 통일하기 위해서이다. 이를 통해 라벨 규칙이 변경될 때 해당 함수만 수정하면 되므로 유지보수가 편리하고, 라벨 변환 기능만 따로 테스트하기도 쉽다.
- MAC 연산으로 Cross와 X 필터의 점수 계산
- epsilon(`1e-9`)을 적용하여 동점 및 판정 불가 처리
- 예상 정답과 실제 판정 결과를 비교하여 PASS/FAIL 출력
- 데이터 형식에 오류가 있으면 해당 패턴을 FAIL로 기록하고 계속 분석

2. 예상 정답은 X이지만, 점수가 같아 UNDECIDED로 판정되었다.
3. `size_13_2`는 두 필터의 점수가 모두 7.5로 동일하다.
4. 예상 정답은 Cross이지만, 동점으로 인해 FAIL 처리되었다.
5. `size_25_1`은 두 필터의 점수가 모두 4.9로 동일하다.
6. 예상 정답은 X이지만, 판정 결과는 UNDECIDED이다.
7. 프로그램은 점수 차이가 epsilon(`1e-9`) 미만이면 판정 불가로 처리한다.

11. 이번 FAIL은 예상 정답과 실제 판정의 불일치이며 프로그램 실행 오류와는 다르다.
12. 향후 필터 가중치 조정 등을 통해 동점 발생을 줄이는 방안을 검토할 수 있다.

### 3.9 크기별 MAC 성능 분석

#### 측정 방법

- `time.perf_counter()`를 사용하여 MAC 함수 실행 시간 측정
- 각 크기에 대해 Cross 패턴 10회, X 패턴 10회 반복 측정
- 두 패턴의 평균 실행 시간을 다시 평균하여 결과 출력
- 측정 단위: 밀리초(ms)
- 측정 대상 크기: 3×3, 5×5, 13×13, 25×25
- 성능 측정에는 자동 생성한 Cross/X 패턴 사용

#### 실제 측정 결과

| 패턴 크기 | 평균 실행 시간(ms) | MAC 곱셈 횟수(N²) |
|---|---:|---:|
| 3×3 | 0.003340 | 9 |
| 5×5 | 0.007985 | 25 |
| 13×13 | 0.027540 | 169 |
| 25×25 | 0.091385 | 625 |

#### 시간 복잡도 분석

- MAC 함수는 이중 `for` 반복문으로 구현하였다.
- 바깥쪽 반복문은 행렬의 N개 행을 순회한다.
- 안쪽 반복문은 각 행의 N개 열을 순회한다.
- 따라서 N×N 행렬에서 총 N²번의 곱셈 및 누적 연산을 수행한다.
- MAC 연산의 시간 복잡도는 **O(N²)**이다.
- 행렬 크기가 커질수록 계산해야 하는 원소 수도 제곱에 비례하여 증가한다.

#### 성능 측정 결과 해석

- 3×3에서는 9회 연산에 평균 0.003340ms가 측정되었다.
- 5×5에서는 25회 연산에 평균 0.007985ms가 측정되었다.
- 13×13에서는 169회 연산에 평균 0.027540ms가 측정되었다.
- 25×25에서는 625회 연산에 평균 0.091385ms가 측정되었다.
- 실제 측정에서 패턴 크기가 증가할수록 실행 시간도 증가하였다.
- 실행 시간은 CPU 상태와 실행 환경에 따라 달라질 수 있다.
- 시간 복잡도 O(N²)는 측정값이 아니라 MAC 함수의 반복문 구조를 근거로 판단하였다.

#### CPU와 NPU의 처리 방식 및 병목 현상

이번 프로젝트의 MAC 연산은 Python의 이중 `for`문을 사용하여 각 행과 열의 숫자를 순서대로 곱하고 더하는 방식으로 구현하였다.

CPU는 다양한 종류의 작업을 처리하는 범용 프로세서이며, NPU는 AI에서 반복적으로 발생하는 대량의 MAC 연산을 병렬로 처리하도록 설계된 장치이다.

패턴 크기가 커지면 계산 횟수가 N²에 비례하여 증가하므로 처리 시간이 길어질 수 있다.

이때 발생할 수 있는 주요 병목 현상은 다음과 같다.

1. **연산 처리:** 순차적으로 수행하는 계산이 많으면 전체 처리 시간이 증가한다.
2. **메모리 대역폭:** 계산에 필요한 데이터를 메모리에서 충분히 빠르게 가져오지 못하면 연산 장치가 대기하게 된다.
3. **데이터 전송:** CPU, 메모리, NPU 사이에서 데이터를 이동하는 데 시간이 걸릴 수 있다.
4. **병렬화의 한계:** 여러 연산을 동시에 처리하더라도 데이터 의존성이나 작업 분배에 따라 성능 향상이 제한될 수 있다.

따라서 대규모 MAC 연산을 효율적으로 처리하려면 병렬 연산뿐 아니라 메모리 접근 방식, 데이터 전송량, 연산 장치의 활용률도 함께 고려해야 한다.

이번 시뮬레이터는 실제 NPU를 사용하지 않고 Python으로 MAC 연산을 순차적으로 구현했으므로, CPU와 NPU의 실제 성능을 비교한 것은 아니다.

**참고:** 3.7의 3×3 측정값(0.002080ms)은 직접 입력 모드에서 입력 패턴과 필터 A를 이용해 측정한 값이고, 3.9의 3×3 측정값(0.003340ms)은 자동 생성한 Cross/X 패턴을 각각 측정한 평균값이다. 측정 대상과 실행 시점이 달라 두 값이 반드시 같을 필요는 없다.

### 3.10 보너스 과제: Cross/X 패턴 자동 생성기

#### 구현 목적

3×3뿐 아니라 5×5, 13×13, 25×25처럼 크기가 큰 패턴을 사용자가 직접 숫자로 입력하지 않고 자동 생성하여 성능 분석에서 활용한다.

#### 구현 방법

`generate_pattern(size, label)` 함수에서 행렬 크기와 모양(`Cross`, `X`)을 입력받는다.

- 크기는 **3 이상의 홀수**만 허용한다. 홀수 크기에서는 가운데 행과 가운데 열이 정확히 하나씩 존재한다.
- `center = size // 2`로 가운데 위치를 계산한다.
- Cross는 `i == center or j == center`인 위치에 `1.0`을 배치한다.
- X는 `i == j or i + j == size - 1`인 두 대각선 위치에 `1.0`을 배치한다.
- 그 외의 위치는 `0.0`으로 채운다.
- 생성된 패턴은 `performance_table()`에서 재사용한다.

**선택 보너스 중 이 패턴 생성기 1개만 구현하였다.** 2차원 배열을 1차원 배열로 변경하여 비교하는 메모리 최적화 보너스는 수행하지 않았다.

## 5. 결과 및 결론

이번 프로젝트에서는 Python의 2차원 리스트와 이중 `for` 반복문을 이용하여 MAC 연산을 직접 구현하였다. 필터와 입력 패턴의 같은 위치에 있는 값을 곱하고 누적하여 Cross/X 패턴의 점수를 계산할 수 있었다.

직접 입력 모드에서 MAC 연산과 입력 오류 처리를 확인하였고, 정확한 동점과 epsilon 허용오차에 따른 판정 불가 처리도 확인하였다.

JSON 자동 분석 모드에서는 총 6개 패턴 중 3개가 PASS, 3개가 FAIL이었다. 실패한 세 패턴은 Cross와 X의 MAC 점수가 동일하여 `UNDECIDED`로 판정되었으므로, 프로그램 실행 오류와 구별하여 원인을 설명하였다.

성능 분석 결과, 패턴의 크기가 커질수록 MAC 연산에서 계산해야 하는 숫자의 개수도 증가함을 확인하였다. 예를 들어 3×3 패턴은 9번, 5×5 패턴은 25번, 25×25 패턴은 625번의 곱셈이 필요하다. 이는 MAC 연산이 이중 for문을 사용하여 모든 행과 열을 계산하기 때문이며, 시간 복잡도는 **O(N²)**이다. 즉, 패턴의 한쪽 길이가 커질수록 계산량은 그 길이의 제곱에 비례하여 증가한다.

또한 보너스 과제로 Cross/X 패턴 자동 생성기를 구현하였다. 이를 통해 사용자가 직접 숫자를 입력하지 않아도 다양한 크기의 패턴을 자동으로 생성하고, MAC 연산 시간을 측정할 수 있었다. 이 과정에서 입력 데이터의 크기가 연산량과 처리 시간에 영향을 미친다는 점을 이해할 수 있었다.
